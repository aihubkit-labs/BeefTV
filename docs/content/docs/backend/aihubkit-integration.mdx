## 使用入口

正式发行按 `scripts/aihubkit/brands.json` 运营清单为每个专属域名分别构建客户端。构建前只向绑定域名请求 `/api/status`，从 `data` 读取 `system_name`、`logo`、`server_address`、`wechat_qrcode` 和 `api_server_address`。只有这项品牌查询使用专属域名；登录、注册、账号、额度、模型目录、上传和所有 AI 生成接口都使用 `api_server_address`。

安装包内嵌该品牌的元数据快照和图标，未登录及离线启动也可识别品牌。客户端名为 `system_name + "TV"`；账号与素材库使用平台名。启动后、窗口重新获得焦点及每分钟刷新品牌信息，失败时保留本包的有效信息。安装图标与包元数据在下次安装包更新时生效，不在线改写签名应用。侧栏仅显示官网和微信二维码，版本号以客户端名为前缀，作为不可点击的文本展示。平台模式隐藏官方算力渠道行，本地模式保留。

贴牌构建在 HTML 首屏加载前注入品牌加载样式，启动、登录过渡及路由加载均使用包内 logo；在线品牌图标加载成功后同步刷新。打包结束或失败时恢复原 HTML，官方构建保留原加载展示。侧栏版本保持单行，空间不足时省略品牌名称、保留版本号，悬停可查看完整名称；侧栏收起时隐藏版本文本。平台模式的 MCP 页面隐藏官方 CLI 安装说明，MCP 连接功能仍可使用。

稳定品牌 ID 决定应用标识和默认数据目录（`<id>TV`），与展示名称解耦。不同品牌各自安装、各自保存工作区；重命名平台不迁移数据目录。不改写用户配置的 S3 桶名、资源名或实际路径。

## 清单驱动的品牌发布

每次正式发布覆盖运营清单中的所有品牌、四种桌面目标和对应便携 ZIP。清单只存稳定 ID 与专属域名，名称、API 地址和图标由接口决定。预检一次冻结全部品牌快照和图标，各平台复用该快照。名称重复、元数据或图标获取失败、任一平台验收失败或发布资产缺失时，工作流不会公开 Release。

本地打包统一使用 `scripts/aihubkit/build.py`，自动识别本机系统和架构，默认读取运营清单中的全部品牌。在仓库根目录运行：

```bash
python3 scripts/aihubkit/build.py
```

Windows 在 PowerShell 中运行同一个文件：

```powershell
python scripts/aihubkit/build.py
```

| 运行系统 | 自动选择的目标 | 安装包 |
| --- | --- | --- |
| macOS / Apple Silicon | `darwin-arm64` | `.dmg` |
| macOS / Intel | `darwin-amd64` | `.dmg` |
| Windows / x64 | `windows-amd64` | `-setup.exe` |
| Ubuntu 24.04 / x64 | `linux-amd64` | `.deb` |

首次运行前安装 Python 3.9 或更新版本、Bun、Go、Git 和对应版本的 Node.js。Go 版本以 `backend/go.mod` 为准，Node 版本以 `scripts/package-agent-host.mjs` 为准。macOS/Linux 会查找 GVM/NVM 中对应的已安装版本，也支持 `BEEFTV_GO_DIR`、`BEEFTV_NODE_RUNTIME`；Node 运行时目录在 Unix 下包含 `bin/node`，Windows 下包含 `node.exe`。

各系统还需准备以下原生工具，入口会预检，缺少时停止并提示：

- macOS：Xcode Command Line Tools（`xcode-select --install`）。
- Windows：PowerShell、NSIS、MSYS2 UCRT64。在 MSYS2 UCRT64 终端中运行 `pacman -S --needed mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-binutils zip`。默认使用 `C:/msys64/ucrt64`，其他安装位置通过 `MSYSTEM_PREFIX` 指定对应的 Windows 绝对路径。NSIS 默认路径为 `C:/Program Files (x86)/NSIS`，其他位置须加入 PATH。正式运行入口使用原生 Windows Python 和 PowerShell。应用安装运行需 WebView2。
- Ubuntu 24.04：运行 `sudo apt-get install build-essential pkg-config libgtk-3-dev libwebkit2gtk-4.1-dev python3-venv git zip`。当前 DEB 依赖以该发行版为基准，不支持在其他 Linux 发行版直接运行此入口。

Python 图标依赖自动装入 `.local/brand-build-venv`。入口准备 Go/Web 依赖，在临时目录调用官方插件打包脚本，再按品牌调用官方原生构建和安装器脚本。macOS/Linux 保留官方本地发布检查；Windows 使用官方 PowerShell 构建入口及 CGO 工具链检查。安装包分别执行 DMG 镜像、PE 文件结构、DEB 元信息检查，实际安装、登录与模型调用另需在对应系统验收。

成功输出到 `dist/aihubkit/<版本>-<平台>-<本次构建时间>/`，包含全部品牌的本机安装包、品牌快照、媒体组件源码包和 `SHA256SUMS.txt`。已下载的 WASM 源码按官方锁文件校验，存于 `.local/cache/ffmpeg-wasm-sources`；连接中断、超时或临时 HTTP 错误最多尝试三次。重新运行会复用有效缓存；源码校验失败或证书错误直接停止。每次使用独立输出目录，同一版本可以重新打包。

任一品牌失败即停止，部分产物保留在 `.partial` 目录，不生成完整校验清单。入口拒绝覆盖 `backend/cmd/desktop/build/bin` 已有产物；如有旧产物，先移走需要保留的文件或使用干净的 worktree。构建后清理本次临时应用，不更新已安装的应用，不上传 GitHub 或创建标签。

追加 `--check` 只检查本机工具链和运营清单，不下载品牌信息或生成安装包；追加 `--brand zmodel` 仅用于单品牌开发验收。该入口只生成本机系统和架构的安装包，不跨系统编译，不替代正式发布的全平台安装包、便携 ZIP 和原生安装验收。

构建入口复用官方脚本、插件、助手运行时和许可证处理。原生构建仍需对应系统和工具链。正式发版前先把功能、运营清单、`AIHUBKIT_VERSION`、`AIHUBKIT_CHANGELOG.md` 合并到远端 `origin/main`，刷新引用并运行 `bash scripts/aihubkit/verify-release-main.sh <发布提交>`，再为该提交创建新的 `aihubkit-v*` 标签。已推送标签不可移动或复用。当前独立发行不使用官方自动更新源；升级下载安装对应品牌的新版。

此 fork 默认启用 aihubkit 适配。打开应用先登录，成功后进入原有工作台。登录页提供注册及邮箱验证码；侧栏底部的「aihubkit 账号」入口提供额度刷新、兑换码充值、分组模型导入和使用日志。账号注册、分组权限与充值规则由 aihubkit 服务决定。

桌面登录页提供「记住账号和密码」：勾选并登录成功后，下次打开应用会自动填充用户名及隐藏显示的密码，仍需点击登录并通过平台验证。退出登录会关闭工作区，但保留已记住的表单；在登录页取消勾选会立即清除已保存的信息。未勾选时成功登录也会清除此前记住的账号密码。服务器部署不提供此功能，可使用浏览器自己的密码管理器。

初次登录会读取默认分组模型，按明确的接口类型选择协议。没有已知接口类型的模型可在账号面板选择已安装的协议后导入。导入保留其他渠道和已选默认模型；模型目录可见不代表已通过实际生成验证。官方 Provider、Protocol、自定义渠道和插件继续使用原有流程。

账号面板「分组与模型」中的“导入所选模型”会创建使用所选分组托管凭据的 aihubkit 渠道。登录后即可获取、导入模型和初始化默认配置，无需额外绑定。通过原有「模型配置」手工创建且已有 API Key 的渠道保持独立，不会被登录流程改写凭据。

分组下拉和选中后的文本显示分组名称及倍率，备注在鼠标悬停时显示；支持按名称和备注搜索。协议下拉支持按名称和请求路径搜索。两者均支持部分匹配且不区分大小写。

首次登录自动初始化三类默认模型：`default-企业版` 分组中版本号最新的 GPT 文本模型使用 OpenAI Chat Completions；`gpt_image_web` 分组的 `gpt-image-2-w` 使用 OpenAI Images；`video_官key` 分组的 `sd-mini-z` 使用 AIHubKit Video。GPT 版本按数字比较，同版本优先无后缀的基础模型。指定模型未匹配时，在对应分组内随机选一个并使用指定协议；账号无权使用该分组或分组为空时跳过，并在登录后提示。是否完成初始化使用独立标记判断，已有配置文件但从未初始化的账号也会执行；完成后再次登录不自动重置。

「已导入模型」右侧的「初始化默认模型配置」按钮可在登录后随时手动执行相同规则：清除所有通过 aihubkit 账号导入的模型渠道，再重建上述三类默认模型及协议。独立配置的渠道保留；指向已清除模型的旧选择一并移除。先获取完整初始化结果，再通过原有模型配置保存流程整体替换；目录请求失败保留原配置。初始化不删除项目、素材或平台推理凭据。

「分组与模型」上方的「已导入模型」直接读取保存的模型配置，展示所有 aihubkit 分组的自动、手动导入记录及协议、默认用途；重新打开面板仍可查看。下方「添加分组模型」用于获取远端目录和追加导入，获取目录时保留已导入模型的协议选择。

## 启停与上游同步

桌面和 server 启动入口通过 `internal/integrations.Open` 选择宿主：`BEEFTV_INTEGRATION=aihubkit`（默认）启用平台登录，`BEEFTV_INTEGRATION=local` 直接使用官方本地运行时。变更后需重启后端。Compose 部署可通过额外的 Compose 覆盖文件给 backend 设置该环境变量。前端从宿主读取会话状态，只有明确的集成接口 404 才使用官方本地模式；认证或网络错误不会降级绕过登录。

每次打开应用需登录 aihubkit，登录后即可使用额度、充值、日志、模型导入和默认模型初始化，不再设置独立的绑定状态。「账号与充值」提供「上传到 aihubkit 素材库」复选框：勾选后，生成所需的参考素材上传使用平台文件服务；取消勾选后，交回 BeefTV 原有流程，按「存储设置」及模型协议处理，可使用自己的 S3 桶。该选择适用于所有模型渠道，不影响模型凭据、导入、初始化及其他原生功能。自配存储未启用或上传失败时，不回退到 aihubkit 上传接口。

账号首次登录、尚无上传设置时默认勾选平台上传。选择保存在该账号目录下的 `aihubkit-preferences.json`，刷新、重启及再次登录均保留，不同账号互不影响。`POST /api/integrations/aihubkit/upload-preference` 接收 `{ "uploadToAIHubkit": true }` 或 `{ "uploadToAIHubkit": false }`，必须携带当前 `X-Aihubkit-Session`，仅有 Cookie 无法修改；写入成功后才更新运行状态并返回会话，保存失败保留原选择，读取失败或文件损坏时不静默恢复默认。切换不改变登录状态、工作区、模型配置或计费规则，不搬迁已有素材。已发出的请求可以继续执行；关闭开关时，已选定平台存储但尚未发起的上传会停止，重试使用当前选择。退出登录仍关闭当前账号工作区。

前端请求适配在桌面启动后安装，仅向当前后端 API 添加桌面授权和账号会话请求头，并直接保留调用方的取消信号。避免多层复制 `Request`：WebKit 在垃圾回收后可能丢失复制链中的取消传播，导致离开画布后实时事件流仍占用连接，最终阻塞画布保存等请求。相关回归可在 `web/` 运行 `bun scripts/aihubkit-transport-smoke.mjs`（先安装 Playwright WebKit）；测试覆盖连续切换、取消后写请求以及请求头隔离，不调用真实模型。

平台后端集中在 `backend/internal/integrations/aihubkit/`，前端集中在 `web/src/integrations/aihubkit/`。官方组合根仅增加 `HostRuntime` 和服务配置 hook；凭据与参考存储通过 `app.Extensions` 的可选端口接入。生成域只选择参考存储实现及检查整批参考链接的有效性，不依赖平台账号实现。视频请求复用现有 `aihubkit-video` 协议插件，不另建生成队列或画布流程。

贴牌规则集中在适配层的 `branding`、`brand.tsx` 和 `scripts/aihubkit/brands.py`。官方代码只提供可选展示端口 `ProductPresentationContext`、既有 appearance store、协议显示名映射，以及 `buildinfo` 的通用发行标识。构建与安装脚本通过可选 `BEEFTV_PRODUCT_NAME`、`BEEFTV_INSTALL_NAME`、`BEEFTV_APP_ICON` 等参数复用，默认值仍是官方产品。合并上游时重点关注侧栏和模型配置页面的展示接入、桌面启动与存储目录、安装器参数和复用工作流；不以旧版自有代码覆盖官方新增业务逻辑。

合并官方更新时重点检查：desktop/server 组合入口、`app.Extensions` 凭据解析、生成执行/预检的参考存储选择、前端启动壳及账号菜单插槽。保留官方最新核心逻辑，再调整这些接入点。每次新需求遵守根 `AGENTS.md` 的「Fork 与上游同步原则」。

## macOS 本机构建与更新

在当前工作区根目录执行统一入口：

```bash
./scripts/aihubkit/update-local-app.sh
```

入口依次确认工具链、下载 Go 依赖、按 `web/bun.lock` 安装前端依赖、从当前源码生成全部协议插件包，再调用官方 `scripts/update-local-beeftv-app.sh` 完成检查、编译、打包、签名校验和本机安装。插件包是 Git 忽略的构建产物，新 worktree 无需从其他工作区复制。

运行前需安装 Python 3.9 或更新版本、Go、Bun 和 Xcode Command Line Tools。依赖及插件准备与品牌打包共用 `scripts/aihubkit/build.py` 的实现。Go 版本要求以 `backend/go.mod` 为准，入口默认使用 `GOTOOLCHAIN=auto` 下载并选择所需版本；显式设置 `GOTOOLCHAIN=local` 时仍遵守该设置，本机版本不足会终止。可用 `BEEFTV_GO_DIR` 指定 Go 安装目录。

Node 运行时复用 `scripts/package-agent-host.mjs` 的版本、平台和架构校验。默认从当前 `node` 命令解析运行时目录；需要指定时，将 `BEEFTV_NODE_RUNTIME` 设置为包含 `bin/node` 的官方 Node 安装目录。入口会将这个目录加入构建进程的 PATH，避免检查和打包使用不同 Node。助手依赖仍由官方打包脚本依据 `agent-host/bun.lock` 在独立暂存目录安装。

协议包每次在 `.local/cache` 下的临时目录重新生成和校验，不改写工作区中的插件源码；生成成功后只同步 `.beeftv-plugin` 产物，并清理已移除插件的旧包。任一步失败都会停止后续操作；入口始终启用官方本地发布检查，不接受 `BEEFTV_SKIP_LOCAL_VERIFY=1` 跳过检查。最终产物校验通过后，由官方脚本更新唯一正式安装路径 `/Applications/BeefTV.app` 并清理构建目录中的临时应用。

该入口仅负责构建编排，不改变 `BEEFTV_INTEGRATION` 的启停选择，也不创建发布标签或修改版本文件。

## 账号与凭据边界

账号宿主仍是单操作者本地工作台，同一后端同时只打开一个账号，不是共享多租户服务。数据目录按平台源和用户 ID 的哈希分隔，路径为 `<data>/aihubkit/accounts/<scope>/`；每个账号拥有独立 SQLite、资源树、模型快照与本地加密密钥。浏览器缓存按相同账号 scope 隔离。不会自动导入原本地工作区的数据。

未选择记住时，登录密码仅用于登录请求。选择记住后，桌面宿主使用 `localcrypto` 将平台源、用户名和密码整体加密保存到 `<data>/aihubkit/login/credentials.enc`；密文和该目录下的加密密钥仅允许当前系统用户读写。自动填充只通过受本次桌面启动令牌和来源校验保护的专用接口读取，不写入浏览器本地存储、普通会话响应或日志。平台源不匹配时不填充；读取或解密失败时显示错误，仍可手动输入后登录。远端登录 Cookie 在后端临时 Cookie jar 内换取管理凭据；管理凭据留在内存。每个模型分组的推理 Key 使用工作区 `localcrypto` 加密保存在 `aihubkit-keys.enc`，前端只保存 `aihubkit:<group>` 引用。托管凭据仅解析到绑定的平台 origin，不能通过自定义 URL 发往其他主机。

应用会话凭据放在内存及 HttpOnly Cookie 中，写请求必须携带当前会话 header；退出后旧会话失效。退出先保存浏览器状态、暂停前端生成消费者，再关闭本机工作区并重新加载页面。上游已接受的任务仍可能执行和计费，退出不等于取消上游任务；再次登录同一账号后由官方任务恢复流程处理已记录任务。

公网部署需使用 HTTPS、明确配置 `CANVAS_CORS_ORIGINS` 并保护数据目录。平台宿主仅支持本地 SQLite；不接受另设远程数据库 URL。重启宿主或迁移数据目录后需重新登录。

## 通用文件上传

临时文件接口是通用存储，适配不按图片限制 MIME，支持图片、视频、音频及其他文件类型。工作台当前在生成参考素材链路使用它；本地导入和保存素材仍由官方资源系统管理。

勾选「上传到 aihubkit 素材库」且模型协议要求上传参考素材以取得公网 URL 时，任务实际执行阶段才会读取当前账号拥有的本地资源，通过管理凭据申请 `POST /v1/temporary-files`，再将原始字节 PUT 到返回的 `upload_url`，使用返回的 `url` 提交模型。该存储选择适用于托管渠道和自行配置的其他模型渠道，不要求用户配置 S3。取消勾选时，所有渠道恢复 BeefTV 原生存储流程。模型协议使用内嵌素材、保留本地文件或用户指定链接时，仍遵循原有协议规则，不强制额外上传。

预检与排队不上传，也不将临时签名 URL 写入排队输入。PUT 客户端不携带平台 Authorization 或 Cookie，只允许票据中的存储请求头；上传与读取地址均遵循 BeefTV 的统一出站策略，包括本地部署和 TUN/Fake-IP 支持。设置 `CANVAS_ALLOW_PRIVATE_UPSTREAMS=false` 可启用严格公网 HTTPS 校验，例外主机通过 `CANVAS_ALLOWED_PRIVATE_UPSTREAM_HOSTS` 配置；链路本地等危险地址仍被拒绝。有效期以接口返回的 `expires_in` 为准，上传完成后再次检查整批链接，避免先上传的文件已过期仍提交生成。链接有效期不足会在生成前报错，需要重新提交。

申请临时上传地址遇到连接中断时，在总计 45 秒内最多尝试三次；该接口只签发地址，不上传文件或提交生成。账号拒绝、业务失败、证书验证失败和取消不重试。连接诊断只显示域名解析、连接、TLS 或等待响应等阶段，不包含原始错误中的凭据和签名 URL。申请失败复用原有参考上传错误合同，提示检查网络，避免误导为用户自配对象存储问题。

文件大小、配额、保留周期与上游抓取时机由线上服务决定，适配不硬编码图片类型或固定大小上限。临时 URL 不应当作永久素材地址。

## 本地接口

全部位于 `/api/integrations/aihubkit/`，使用工作台标准 `{ code, data, msg, reason }` 信封。除 `brand`、`session` 查询、登录/注册/验证码及桌面登录表单接口外，均要求已登录。`GET brand` 返回安装包品牌快照，`GET brand?refresh=1` 在一分钟内至多刷新一次；仍受桌面启动令牌与来源校验保护。桌面登录表单接口仅在未打开账号工作区时可用，必须携带 `X-Desktop-Token` 和 `X-Aihubkit-Client: 1`，响应禁止缓存；服务器模式拒绝访问。

未登录的桌面 `session` 响应以 `rememberLoginAvailable: true` 表示支持表单记忆。`login` 的可选布尔字段 `rememberCredentials` 默认为 `false`，仅在账号验证和工作区启动成功后保存或清除表单，错误密码不会覆盖已有记录；服务器模式拒绝开启此选项。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `session` | 集成启用与当前会话状态 |
| POST | `login` / `register` / `verification` | 登录、注册、发送验证码 |
| POST / DELETE | `login-form` | 桌面登录页读取或清除加密保存的表单；不创建登录会话 |
| GET | `self` / `logs` | 当前账号额度、脱敏使用日志 |
| POST | `upload-preference` | 持久保存当前账号的参考素材上传方式，返回更新后的会话 |
| POST | `catalog` | 读取授权分组模型目录 |
| POST | `default-model-config` | 按首次登录规则准备默认模型配置及跳过提示，仅返回托管渠道；客户端通过原有模型配置 API 保存替换结果 |
| POST | `topup` | 兑换码充值 |
| POST | `logout` | 关闭账号工作区并使会话失效 |

外部协议见 [账号系统接口](https://86bdknokqu.apifox.cn/9446929m0) 和 [临时文件接口](https://86bdknokqu.apifox.cn/9496843m0)。
